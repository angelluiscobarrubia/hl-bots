NOTAS SOBRE LA ESTRUCTURA
────────────────────────────────────────────────────────────────────────

1. `backend/src/core/` no importa nada de `adapters/` ni `api/` (regla hexagonal).
   `core` solo expone entidades, ports, services y modelos SQLAlchemy.

2. `backend/strategies/` está al mismo nivel que `backend/src/` a propósito:
   - Se carga como paquete top-level (`import strategies.mi_estrategia`)
   - Permite que las estrategias sean código "externo" al core (plugins)
   - El watcher solo observa este directorio

3. `backend/alembic/` separado de `src/` para que las migraciones sean
   operacionales (versionadas, ejecutables con CLI), no parte del código
   de aplicación que se importa.

4. `frontend/src/types/` está vacío: cuando se estabilicen los schemas de
   la API backend, se generarán tipos TypeScript con `openapi-typescript`
   (pendiente de añadir como devDependency).

5. `doc/` contiene TODO lo conceptual. NO es código; es la fuente de verdad
   de las decisiones arquitectónicas y operativas.
